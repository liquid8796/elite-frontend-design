# Baseline Skin Packs

These packs are **Deterministic Design Scaffolds** for execution modes that need a coherent baseline. They are not clone recipes and they are not tied to a model label.

## Selection Rule

Use **1 archetype + 1 skin + 1 composition grammar**. Do not mix multiple skins unless the design contract explicitly defines the boundary.

## Adaptive Execution Modes

Skin selection is controlled by Adaptive Capability Routing, not by asking whether a model is strong or weak. **GUIDED is the default** when evidence is inconclusive.

- **LOCKED** ? choose exactly one skin, materialize its Token Scaffold, keep Skin Lock fixed, and allow only narrow Controlled Mutation.
- **GUIDED** ? choose one skin as a coherent baseline, then allow bounded token/composition changes and one bespoke signature while keeping the core visual system stable.
- **BESPOKE** ? skins are optional references rather than locks; custom art direction is allowed only after a fully resolved Design Preflight and with strong rendered QA.

Use the **Task Complexity Score** and **Design Preflight** from the design-intelligence module to choose the amount of scaffolding. High complexity raises the evidence bar; it never means "automatically choose BESPOKE."

## Skin Lock vs Controlled Mutation

**Skin Lock** protects coherence. **Controlled Mutation** creates identity.
