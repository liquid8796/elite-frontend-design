# Baseline Skin: Developer Infrastructure

## Use when
Use when APIs, infrastructure, developer tools, observability, deployment, data, or technical SaaS must persuade through truthful implementation and operational evidence.

## Evidence Anchor
`../sites/resend.com.md` is an **audited evidence anchor** for this skin. Transfer mechanisms, not Resend branding, exact cube, exact fonts, copy, or page order.

## Deterministic Design Scaffold
Use **Product Evidence Before Feature Claims**, **Code as Product Proof**, and **Responsive Fidelity Substitution** where they fit.

## Token Scaffold
- near-black/dark-neutral shell with 3–7% luminance steps between surfaces;
- text 90–96% white; border 8–13% white equivalent;
- semantic color budget for syntax, status, selection, data, and one brand accent;
- radius 8 / 12 / 16px; mono only for code/data/meta;
- container 1180–1280px; code panels remain readable rather than decorative texture.

## Composition Grammar
- hero: technical category promise + one credible product/signature proof;
- claim -> inspectable code/product state -> explanation;
- functional tabs only for real visitor contexts;
- logs, editor, analytics, sandbox/test mode, and operational state can become marketing media.

## Skin Lock
Lock technical typography roles, surface hierarchy, radius, spacing, actions, and state-transition language.

## Controlled Mutation
May mutate accent, signature proof, ecosystem selector, hero layout, and product-specific operational evidence.

## Responsive Contract
Keep real code/product proof readable; use Responsive Fidelity Substitution for expensive signature media.

## Anti-Template Guard
No fake terminal wallpaper, meaningless code, or generic purple glow as a substitute for product truth.

## QA Rubric
Verify code authenticity, product-state credibility, semantic color use, functional tabs, mobile readability, and proof hierarchy.
