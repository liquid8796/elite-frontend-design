# Baseline Skin: Whimsical World Portfolio

Tobi Mallory full-site audited evidence anchor: ../sites/tobi-mallory.framer.website.md

This skin serves personal portfolios, small studios, illustrators, multidisciplinary makers, and creative service businesses where a recurring fictional/collectible world can organize real work without hiding professional proof.

Tobi Mallory contributes the audited mechanisms: World Metaphor as Information Architecture, Taxonomy as Visual Physics, Mnemonic Case-Study Encoding, Metaphor Translation Contract, Project Evolution as Relationship Proof, illustrated DOM worldbuilding, and zero-overflow responsive preservation of the world vocabulary.

This is not a mascot skin. The world layer must carry navigation, memory, taxonomy, or proof value.

## Use when

Use for:
- independent creative portfolios with original visual assets;
- multidisciplinary designers/developers/illustrators;
- small studios with a small number of clear disciplines;
- creative service businesses that can package work into memorable categories;
- collections/catalogs where each record can own a mnemonic identity;
- playful educational/cultural experiences with stable taxonomy.

Avoid as the primary skin for regulated enterprise products, dense admin tools, serious financial/legal workflows, generic corporate sites, or any project where invented vocabulary would add friction.

## Deterministic Design Scaffold

Build one coherent world model before styling pages.

Define:
1. the real content entities;
2. one metaphor term for each entity type;
3. one stable taxonomy;
4. one global shell;
5. one mnemonic identity system for records/projects;
6. one conventional fallback vocabulary for accessibility/search/first-time decoding.

Do not invent lore after the page structure is built. The world model should explain the structure.

## Token Scaffold

- global shell: warm neutral or one low-chroma world surface;
- primary ink: one high-contrast dark family;
- category accents: 4-7 distinct but coordinated families;
- display role: friendly, high-character grotesk/serif/sans with large mass;
- body role: quieter, highly readable sans;
- metadata role: mono or compact utility sans;
- optional illustration line/shape language shared across categories;
- controls: conventional hit areas and labels even when visually themed;
- display scale: ~72-168px desktop for identity moments, ~44-80px mobile;
- route H1: ~72-120px desktop, ~44-60px mobile;
- body: ~16-20px;
- container: ~1160-1360px;
- section gaps: ~96-176px desktop;
- category color must never be the sole semantic signal.

Do not copy Tobi Mallory's exact cream/plum palette or six accent values. Preserve the logic: stable shell + category-specific visual physics.

## Composition Grammar

### Home

Reliable sequence:
1. identity + short real-world role;
2. teach the world vocabulary;
3. featured collection/work;
4. one proof/detail preview;
5. taxonomy/types;
6. optional evolution/relationship proof;
7. map/world overview;
8. stats/achievements only when truthful;
9. service packages;
10. process;
11. about/origin of the world system;
12. content/logbook;
13. contact/save-point conversion.

The home should teach how to read the world before asking visitors to explore it deeply.

### Collection / portfolio index

Each record should expose:
- mnemonic identity;
- conventional project/client identity;
- category/type;
- image/illustration;
- short job/premise;
- obvious route into the detail.

Numbering is optional. Use it only if collection behavior benefits from sequence/completion.

### Case-study / field-entry detail

Preferred stack:
- mnemonic/project title;
- number/type/category;
- one-line premise;
- client / year / scope;
- result/outcome;
- brief/problem;
- intervention / what was made;
- evidence/result;
- related/evolved entries;
- conventional next action.

Mnemonic Case-Study Encoding must sit on top of real proof, never replace it.

### Taxonomy / types

Use one category source of truth.

Each type may control:
- accent;
- badge/emblem;
- illustration family;
- local surface tint;
- short motion behavior;
- map/world location.

Keep the actual discipline/category name visible as text.

### World map / taxonomy overview

Use a map/spatial overview only when it helps visitors understand how categories relate.

Every destination must also be available through conventional links/list semantics.

### Services / quests

Playful service naming may wrap:
- outcome;
- price/range when appropriate;
- duration;
- deliverables;
- process;
- CTA.

Do not make users decode lore to learn what they can buy.

### Journal / logbook

Keep editorial reading calmer than the collection/world showcase.

Category/date/read-time/title should remain conventional even when the route is branded as a Logbook.

### Contact / save point

Reduce novelty.

Use ordinary:
- name;
- email;
- project/service selector;
- message;
- submit action;
- response expectation.

Themed heading/CTA copy can add personality, but form labels must remain explicit.

## World Metaphor as Information Architecture

Every world term must map to one stable real-world concept.

Write the mapping before implementation:

**world term -> real user job -> route/content family -> conventional fallback**

Example categories:
- collection -> portfolio;
- type/class -> discipline;
- quest -> service;
- map/island -> category navigation;
- badge/seal -> achievement;
- save point -> contact.

If two metaphor terms map to the same job, simplify.

## Taxonomy as Visual Physics

Category identity may propagate through:
- color;
- badge;
- illustration;
- local surface;
- metadata;
- map location;
- bounded motion.

Lock the mapping site-wide.

Do not let category styling fragment the global shell into unrelated mini-sites.

## Mnemonic Case-Study Encoding

Use a short name/object/creature/number to make work memorable.

Always retain:
- client/product;
- scope;
- date/year;
- actual problem;
- actual intervention;
- actual result;
- related work when relevant.

Never invent a cute mnemonic that makes the underlying work harder to find or understand.

## Metaphor Translation Contract

On first exposure, visitors must be able to decode the real job within seconds.

Conventional cues may include:
- route URL;
- page title/meta description;
- subtitle;
- category label;
- form field label;
- price/timeline;
- client/work metadata;
- accessible name.

World vocabulary should improve memory after decoding, not block decoding.

## Project Evolution as Relationship Proof

Optional when a later engagement genuinely grows from an earlier one.

Show:
- original project;
- why it needed to evolve;
- expanded scope;
- what was retained;
- what changed;
- new observable result.

Use this to prove continuity/system maturity, not to manufacture narrative links.

## Skin Lock

Lock:
- world-to-real vocabulary mapping;
- global shell;
- typography roles;
- category taxonomy;
- category visual mapping;
- case-study evidence fields;
- control/accessibility vocabulary;
- illustration grammar;
- motion ownership;
- responsive identity priorities.

## Controlled Mutation

May mutate:
- metaphor/world theme;
- number/names of categories;
- illustration style;
- shell warmth/darkness;
- category accent families;
- display typography;
- map representation;
- collection numbering;
- amount of animation;
- service-package names;
- one signature interaction.

Must mutate away from Tobi Mallory:
- Tobi name/identity;
- Fieldbook/Isles/Quest/Save Point wording unless independently appropriate;
- creature names Bezzle, Curvix, Pixit, Mote, Lumpkin, Hum, Dart;
- exact six type names/mappings;
- exact project/client stories;
- exact palette;
- original illustrations;
- copy and metrics.

## Responsive Contract

Preserve:
- world vocabulary;
- category names;
- one mnemonic cue per record;
- category visual identity;
- project proof;
- service scope/price/timing;
- conventional action labels.

Adapt:
- reduce giant display type deliberately;
- stack collection grids;
- convert hover-only flips to tap/focus or always-visible critical metadata;
- simplify world maps into touch-safe destinations/list fallbacks;
- remove decorative animation before removing meaning;
- keep outer document horizontal overflow at zero;
- allow mobile pages to become taller rather than crushing the world into tiny cards.

Mobile does not need desktop hover theater. It needs the same information/world identity through a touch-native mechanism.

## Motion Language

Prefer lightweight DOM/illustration choreography:
- creature/object entrance;
- card flip/turn;
- badge response;
- scroll-linked hatch/process illustration;
- map destination feedback;
- short category transitions.

Keep one motion owner per section.

Do not add WebGL merely because the site uses game-like language.

Reduced motion:
- remove walk/float/continuous drift;
- keep final illustrated state;
- keep project/category identity visible;
- replace flips with direct state or simple opacity transition.

## Anti-Template Guard

High-risk imitation bundle:
- cream background;
- chunky Bricolage-like display type;
- Space Mono labels;
- six rainbow category colors;
- cute creatures;
- RPG quest language;
- map/islands;
- numbered project cards;
- badges/stats/save-point footer.

If several appear together, redesign the metaphor, taxonomy, illustration grammar, type roles, map structure, and collection behavior so the new system belongs to the actual person/product.

Do not create mascots solely to make a portfolio look original.

## QA Rubric

Before signoff verify:
- every metaphor term maps to one real job;
- first-time visitors can decode the site without lore knowledge;
- category meaning is not color-only;
- project details retain client/scope/result evidence;
- service details expose concrete deliverables/timing/pricing where promised;
- hover content is accessible by keyboard/touch;
- every detail/article has one meaningful H1;
- document-level horizontal overflow is zero at representative mobile widths;
- animation remains optional to comprehension;
- legal/contact/404 stay operationally clear;
- canonical/sitemap host points to the intended public domain;
- no source creature names/artwork/copy/metrics were copied.

Pass only when the world layer improves memory and navigation while professional proof remains stronger than the gimmick.
