# Baseline Skin: Bento Product

## Use when
Use when a product has genuinely parallel capabilities that benefit from quick visual comparison. Do not use merely because bento is fashionable.

## Deterministic Design Scaffold
Bento is information architecture first and visual pattern second.

## Token Scaffold
- neutral light/dark page; cards differ from page by a small luminance step;
- border 8–12% contrast; one radius family, typically 16–20px;
- grid gap 16–24px desktop, 12–16px mobile;
- inner padding 24–36px; container 1180–1280px;
- card headings remain below page-level heading scale.

## Composition Grammar
- max 5–7 tiles in one major bento chapter;
- tile size follows importance/content, not random masonry;
- each tile proves one capability with real state, data, media, or concise explanation;
- one large anchor tile; follow bento with open-layout sections.

## Skin Lock
Lock grid gap, radius family, surface hierarchy, internal padding, type scale, and tile interaction language.

## Controlled Mutation
May mutate tile proportions according to real content, proof media, accent, and the anchor capability.

## Responsive Contract
Convert to a deliberate single-column or small-grid priority order; never preserve desktop masonry at the cost of reading order.

## Anti-Template Guard
The entire page must not become a wall of rounded tiles. Run Template Archetype Firewall aggressively.

## QA Rubric
Verify tile hierarchy matches information importance, no empty decorative tiles exist, mobile order is semantic, and open-layout relief exists.
