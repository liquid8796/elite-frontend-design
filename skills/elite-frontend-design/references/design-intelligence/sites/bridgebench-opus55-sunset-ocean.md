# BridgeBench Opus 5.5 — Sunset Ocean: Source-and-Prompt Distillation

## Reference, contract and provenance

**Actual local source:** `D:\Project\test\bridgebench-opus55-sunset-ocean` (source file `index.html`, original `bridgebench-original.html`). Startup `start.bat` launches `python -m http.server 8765 --bind 127.0.0.1`, with UI served at `http://127.0.0.1:8765/`. The source's README attributes the HTML to the Claude Opus 5.5 public BridgeBench Sunset Ocean benchmark artifact and links the public benchmark and artifact URL. This audit **does not independently verify the original model attribution**; local README/original pair are the evidence. No source file was redesigned as part of this distillation.

**Supplied prompt:** user-attached `prompt.txt` (Sunset Ocean, 168 lines), also present in source folder. It specifies one seamless cinematic, photoreal panoramic open sea, sun low at sunset, long continuous heavy waves, glitter trail, cloud-lit sky, near-water POV and a hidden/optional debug panel. The priorities are **image realism → wave motion → 60 FPS at 1080p**. Mandatory implementation: single self-contained HTML + Three.js/CDN imports, runtime procedural textures, Gerstner displacement, two scrolling ripple normal maps, Fresnel/sky/specular/foam, analytic physically motivated scattering sky, dynamic sun, camera drift/bob, ACES/sRGB/bloom/AA, low/high quality and resize. Acceptance T1–T11 are enumerated in the trace ledger, not assumed passed.

**Scope:** one single-route WebGL simulation, **not an agency site or a multiscreen website**. Route inventory only `/` (200) under local HTTP. Controls: Sea State slider 0..1 (step .01), Sun Elevation 1..12 degrees (step .1), and `window.BridgeBenchTaskApi` with `init/reset/getState/getScore/destroy`. The always-visible bottom-left `#ui` is **not hidden by default** and therefore deviates from the prompt's immersive no-UI goal.

## Source architecture (not an inferred shader)

The original HTML is roughly 16.9 KB, a single vanilla HTML ES module with an import map to Three.js **0.182.0**. `index.html` differs primarily by local vendor `./vendor/...` paths and blank data/favicon; local vendor has both `three.module.min.js` and `three.core.min.js`. **No npm, bundler or downloaded texture.** However, the local adaptation must be served over HTTP: README explicitly discourages `file://`, and an independent Chrome file protocol check yielded **zero canvas, no BridgeBench API and 2 console errors**. It does not meet the prompt's literal "open the HTML file directly" acceptance. When running under `start.bat` HTTP, images/HTML are served locally; no external CDN scripts are needed. The visible scene is generated by shader code, not stock Three.js `Water.js`.

**Renderer and camera:** `THREE.WebGLRenderer({antialias:true,powerPreference:'high-performance'})`, DPR max **1.5**, tone mapping **ACESFilmicToneMapping**, exposure **1.2** then adjusted by sun elevation, output `SRGBColorSpace`. Perspective FOV 52°, camera ~2.3+ m above sea, pitch around -3°, slow sine pitch/roll under 1°. Camera XZ remains fixed at (0,0); water ring is static and world-centred, not re-centred to follow camera translations. Camera height depends on **sum of wave amplitudes**, NOT sampled local wave height, so do not claim physically accurate crest-relative bobbing. `onResize` updates camera aspect, DPR and renderer size in code.

**Ocean geometry:** `SA=384`, `SR=330` angular × radial annular grid; **(331×385)=127,435 vertices** and **(330×384×2)=253,440 indexed triangles**. Radial distance `r(i)=1.2*(1.031^i-1)` creates dense near rings, sparse far rings, with radius ~28–29 km. A single `BufferGeometry` is allocated once; no per-frame CPU geometry rebuild, `water.frustumCulled=false`. Not a floating-origin/clipmap solution for a freely moving camera.

**Gerstner displacement:** `NW=8` waves with characteristic wavelengths `[62,41,27,17.5,11.3,7.2,4.6,3.0]` metres and randomized wavelength ±6%; shader phase `theta=k*dot(dir,P)-sqrt(9.81*k)*time+phase`. Horizontal `uQA*cos(theta)` and vertical `uAmp*sin(theta)` components sharpen crests and flatten troughs. Analytical tangent/bitangent derivatives are recomputed in **fragment shader**, giving `cross(B,T)` water normal; `J=T.x*B.z-T.z*B.x` Jacobian approximates crest compression for foam. Build seeds use deterministic `mulberry32`; smooth Sea State transitions use `1-exp(-dt*3.5)`. High-frequency micro detail is **16 direct multi-frequency ripple wave slopes** in fragment (wavelength ~2.4 m decaying ×.86) with screen-space derivative filtering and ambient roughness, **not** the prompt's two independently scrolling procedural **normal-map textures**. The analytic waves are dispersed by deep-water `sqrt(g*k)` angular frequency. Actual temporal coherency/60 s no-repeat has not been fully established.

**Sky:** one large inward facing sphere (`SphereGeometry(40000,64,32)`, `ShaderMaterial` BackSide). `COMMON` shader includes `hash12`, `vnoise`, 5-octave `fbm`, `clouds(d,mu,az,hor)`, and `skyColor(d,disc)`. Sky blends warm sun-aligned horizon, cool antisolar horizon, mid and zenith colors, sun-direction Mie-like powers, sun disc with very high directional radiance, and direction/height-dependent warm versus cool procedural cloud coloration. This is **hand-tuned analytic gradient + directional lobes**, NOT a fully physically parameterized Rayleigh/Mie/Preetham/Hosek-Wilkie atmosphere. Avoid asserting it implements those formal scattering equations. Clouds are composed **inside sky shader**, not a separate dedicated cloud mesh/draw call.

**Reflection and water BRDF:** dynamic `WebGLCubeRenderTarget(256)` half-float with mips, captured via `CubeCamera.update(renderer,scene)` **every frame while ocean hidden**. Sampling reflected directions from the same sky shader avoids mismatched sky colors. Water Fresnel = `0.02+0.98*(1-n·v)^5` (Schlick). Water highlight uses an exponential **Beckmann-like NDF** `D=exp(-(1-nh²)/(nh²*m²))/(pi*m²*nh⁴)` with microvariance `vr` and directed sun. Along-grazing reflection creates a broken bright path. Source uses one main analytic lobe plus ripple variance; do not claim a separate explicit broad second GGX lobe is implemented. Deep teal base `(0.018,0.075,0.095)` shifts through turquoise `(0.06,0.30,0.28)` via crest height + light-direction; foam is Jacobian, FBM threshold and footprint gated, eased off for low sea states. Distant water fog blends to near-horizon environment color.

**Compositing:** ACES/sRGB in each fragment, native renderer MSAA; tiny hash film grain; **no EffectComposer, UnrealBloomPass, SMAA/FXAA, vignette post-pass or explicit quality Low/High toggle**. Because `cubeCam.update` renders 6 sky faces **every animation frame** plus normal final frame, do not repeat the prompt's desired "one draw call water, one sky, one cloud" as an observed runtime budget. Sky procedural FBM is relatively expensive and cube capture every frame warrants measured profiling/refresh throttling before reusing unchanged.

## Transferable Engineering Design DNA

1. **World-first, one-canvas experience** — no marketing card shell, no site routes; camera and physically plausible sky/water share the frame.
2. **Radial resolution allocation** — near field gets triangle detail while far field extends to sky, but keep draw/vertex cost in measured budget and re-centre if the camera can travel.
3. **Dispersed Gerstner spectra** — seeded cross-direction amplitude/wavelength/phase, analytic normals, footprint-filtered high-frequency detail and Jacobian foam; don't substitute a noisy height-only sine wave.
4. **One sun state across render systems** — drive sun disc, procedural sky, cloud tint, water specular, scattering, exposure and fog coherently via shared uniforms.
5. **Environment-consistent mirror** — near-horizon sky reflection from same sky model, with Schlick Fresnel and physically motivated NDF. For production performance, cache/reduce cubemap updates when the sky evolves slowly instead of blindly adding six passes each frame.
6. **High/low frequency normal separation** — this source's wave slopes are spatially filtered procedural ripples; the prompt's two scrolled normal textures are an **unimplemented alternative** and should be authored independently in future implementations if required.
7. **Meaningful exposed simulation controls** — Sea State and Sun Elevation drive uniform inputs, deterministic reset and testable task API; default UI/visual hide behavior is a separate product requirement.
8. **Full-screen media render with fallback** — visual canvas is the product; validate GPU support, loading/readiness, reduced-motion capture, WebGL context loss, file-vs-HTTP and true desktop/mobile resize.
9. **Physics vs art-directed approximation** — "Rayleigh/Mie-like" look from hand-tuned directional palette may be effective but not mathematically equivalent to physical atmosphere scattering; report fidelity honestly.
10. **Code-review plus render-proof QA** — compare exact T1–T11 prompt acceptance to source AND browser. Shader presence alone does not establish photographic illusion, horizon anti-aliasing, true 60 FPS or seamless minute-long movement.

## Source-specific pitfalls

Visible always-on panel, direct `file://` failure, no dedicated true normal-map layers, no true atmospheric model, no bloom/vignette, no Low/High, static camera XZ and no wave-following height, expensive per-frame cubemap pass, mobile backbuffer not verified, and high frame time on SwiftShader. Avoid calling these features implemented merely because the prompt demanded them. The local vendor import adaptation diverges from the original "CDN only, zero asset files" restriction while solving portability.

**No user source patch was performed** in this distillation: suggestions above are transferable toolkit rules and prompt-gap findings, not claims that the source was rewritten to fully meet acceptance.
